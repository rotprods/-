## Portfolio conclusions

### P0 — immediately stop
- additional cosmetic/microdetail passes on any asset whose current state is `BLOCKOUT` or `PROXY` and whose intended exposure is hero/close-up;
- using object count, mesh count, triangle count, LOD existence or deterministic rebuild as evidence of hero fidelity;
- treating calibration textures as final production texture art;
- treating raw reconstruction as a final game asset.

### P1 — preserve and compound
- world layout;
- scale/camera/traversal contracts;
- collision and physics evidence;
- streaming cells;
- procedural/systemic generators;
- LOD/HLOD derivation systems;
- engine import tooling;
- material-causality grammars;
- asset IDs, provenance and receipts.

### P2 — build the missing source layer
Recommended first portfolio pilots:
1. `NACRE-LOOK-ARCHIVE-CHAMBER-001` — already has correct bakeoff architecture.
2. one ELYSIUM hero arcology / EDEN identity asset — tests hard-surface/architectural reconstruction.
3. THALASSA or one LEVIATHAN creature — tests organic hero reconstruction/sculpt route.
4. one SYLVA primary hero root — tests procedural source + high-frequency organic material/detail route.

Do not start all four simultaneously until the first bakeoff produces a reusable receipt format and measured cost/quality data.

## Promotion policy

A world may contain assets in different fidelity states simultaneously. `DENSE_AAA_WORLD` or stronger X100 language does not imply every object is `HERO_QUALIFIED`. Hero density is intentionally sparse; systemic breadth is intentionally cheaper.

The correct relationship is:

`WORLD QUALITY = qualified hero identity + coherent support + efficient systemic breadth + gameplay/runtime evidence`.
